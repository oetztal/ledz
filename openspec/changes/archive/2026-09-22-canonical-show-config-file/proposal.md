## Why

`scripts/show_variants.json` currently plays two roles at once: it is the curated showcase list that drives the docs gallery, and it is the de-facto source for the factory default parameters of every show. The two roles collide on the file's schema — the role of "factory default" is currently signalled only by the variant being *named* `"default"` (or by convention: `"warm"`, `"scroll"`, `"bifurcation"`, etc.). That naming convention is invisible to any consumer that does not already know it, and the JSON is not actually self-describing for the factory-default role because eight of the twelve shows have a `"default"` variant whose `params` is `{}` — i.e. the JSON delegates the default to the C++ `|` fallback.

The drift this allows is already real:

- **MorseCode message**: the JSON `"hello"` variant sets `message="HELLO WORLD"`; the C++ factory fallback says `"HELLO"`; the constructor default in `MorseCode.h:42` says `"HELLO WORLD!"`; `data/control.html:277` shows `"HELLO WORLD!"` in the input. Four different strings.
- **Starlight "cool" preset**: gallery has `length=100, fade=300`; `src/TouchController.cpp:52` has `length=5000, fade=1000` for the same intent. Drift between two on-device consumers.
- **TheaterChase "tight"**: gallery says `num_steps_per_cycle=8`; touch says `num_steps_per_cycle=42` and `num_steps_per_cycle=84`. No overlap.

Step 1 of the consolidation is to make the JSON self-describing for both roles and structurally separate them, so every downstream consumer — gallery renderer today, C++ factory and web UI in later changes — can read one source with one schema.

## What Changes

- Restructure `scripts/show_variants.json` so each show has a top-level `default` object (the factory default parameters) alongside a `variants` array (curated presets). The default is structurally distinct from the variants, not just conventionally named.
- Materialise every variant's `params` so the JSON is fully self-describing for every key the C++ factory reads via `doc["key"] | value`. No variant's `params` will be `{}` after this change; the empty-object convention disappears.
- Update `scripts/build_pages.py` so `--all` renders the default as a synthetic first entry alongside each show's variants, and so the gallery's `index.html` lists the default first under each show's description.
- Update the `_comment` at the top of `scripts/show_variants.json` to describe the file's two roles.
- Converge the four-string MorseCode drift on `"HELLO WORLD"` as the canonical default message. The JSON's `default` for `MorseCode` declares `"HELLO WORLD"`; the C++ `| "HELLO"` fallback and the `MorseCode.h:42` ctor default and the `control.html` input value remain in their current state for this change, with the convergence deferred to a follow-up.
- Lift `Mandelbrot`'s `iterations: 1500` from per-variant to show level so the same value applies to both the default and the seven variants.
- No C++ source change, no web UI change, no docs change. `ShowFactory`'s `|` fallbacks remain the runtime fallback for now; making the JSON the runtime source is a follow-up change.

## Capabilities

### New Capabilities

- `canonical-show-config`: defines `scripts/show_variants.json` as the single canonical source of every show's factory default parameters and curated preset parameters, with a schema that makes both roles explicit at the data-model level.

### Modified Capabilities

- `show-simulator`: the renderer (`scripts/build_pages.py`) reads the new `default` field in addition to the existing `variants` array and renders the default as the first variant under each show's section.

## Impact

- `scripts/show_variants.json`: structural change — every show entry gains a `default` object and the variant that was previously named to do that role moves out of `variants`. Eight currently-empty `params` objects become fully materialised. `Mandelbrot`'s per-variant `iterations` lifts to the show body. Top-of-file `_comment` is rewritten.
- `scripts/build_pages.py`: small extension — `_resolve_variants` (or equivalent) reads `body["default"]` as a synthetic variant named `"default"` with label `"Factory default"`, prepended to the existing variants. The `index.html` template is unchanged; the gallery layout keeps "default first, then variants" because the renderer now emits the default first.
- No firmware change. No `data/*.html` change. No `docs/*.md` change. No new HTTP endpoints. No NVS schema change.
- `docs/show_previews/`: regenerated by `python3 scripts/build_pages.py --all docs/show_previews --landing --seed 42`. PNG outputs are byte-for-byte identical to the pre-change renderings for every variant and 11 of 12 default renders. The 12th show, `Mandelbrot`, differs in ~0.08% of pixels because ArduinoJson 7's decimal parser rounds `-0.3616` and `-0.3156` to floats 1 ULP away from the C++ literal (`beb923a2` vs `beb923a3`, `bea19652` vs `bea19653`). This is a known ArduinoJson parser limitation, not a defect in the materialisation; the divergence is visually imperceptible. The only intentional output change is the appearance of new `*_default.png` files for shows whose default was previously rendered only as `{}` (i.e. every show — these are technically new files in the output directory).
