## Why

The `canonical-show-config-file` change made `scripts/show_variants.json` the canonical source of every show's default parameters and curated presets, and explicitly named the MorseCode four-string drift as the headline example of the problem the capability solves. Step 1 fixed one of the four strings (the JSON). Three drifted locations remain: `src/show/factory/ShowFactory.cpp:105` declares `| "HELLO"`, `src/show/MorseCode.h:42` declares `"HELLO WORLD!"`, and `data/control.html:277` declares `value="HELLO WORLD!"`. The current `canonical-show-config` spec requirement `Default.params for MorseCode uses "HELLO WORLD"` already calls out that the C++ factory, ctor default, and HTML input "are out of scope … and SHALL be reconciled to `"HELLO WORLD"` in a follow-up change." This change is that follow-up.

## What Changes

- Change `src/show/factory/ShowFactory.cpp:105` from `doc["message"] | "HELLO"` to `doc["message"] | "HELLO WORLD"` so the C++ factory fallback declares the same string the JSON default declares.
- Change `src/show/MorseCode.h:42` constructor default from `"HELLO WORLD!"` to `"HELLO WORLD"`. The constructor default is documentation only — `ShowFactory` is the only caller — but it must not contradict the JSON or the factory.
- Change `data/control.html:277` `<input>` value from `"HELLO WORLD!"` to `"HELLO WORLD"` so the on-screen default matches the JSON default. The gzipped output `src/generated/control_gz.h` is regenerated automatically by `scripts/compress_web.py` on the next `pio run`.
- Update `openspec/specs/canonical-show-config/spec.md` requirement `Default.params for MorseCode uses "HELLO WORLD"` to require that all four locations — JSON, factory fallback, constructor default, HTML input value — declare the identical string `"HELLO WORLD"`. Remove the "out of scope for this capability" clause.

**Behavioural note.** `POST /api/show {"name":"MorseCode","params":{}}` today produces a strip state that scrolls the message `"HELLO"`. After this change it produces a strip state that scrolls `"HELLO WORLD"`. This is the intentional convergence; it is the one runtime behaviour change in the canonical-show-config trajectory, and it is the headline example the prior change proposed to fix.

Users who have an explicitly-saved MorseCode `params_json` in NVS (carrying `"message":"HELLO"` or any other string) are unaffected — `ShowFactory` honours whatever the JSON carries. Only the empty-params path changes.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `canonical-show-config`: the requirement `Default.params for MorseCode uses "HELLO WORLD"` is amended. The four-location declaration rule replaces the current "out of scope until follow-up" wording, and the C++ factory fallback, constructor default, and HTML input value each become covered by the requirement instead of being explicitly excluded.

## Impact

- `src/show/factory/ShowFactory.cpp:105` — one literal change.
- `src/show/MorseCode.h:42` — one literal change.
- `data/control.html:277` — one literal change.
- `src/generated/control_gz.h` — regenerated by `scripts/compress_web.py` PlatformIO `pre:` hook on the next build (no manual edit). The on-the-wire HTML is identical to `data/control.html` modulo gz.
- `openspec/specs/canonical-show-config/spec.md` — one requirement edited.
- No NVS schema change. No HTTP endpoint change. No `scripts/show_variants.json` change. No `scripts/build_pages.py` change. No firmware build flag change.
- No new tests required: the change is a literal substitution with no structural code change; the existing `pio test -e native` suite continues to exercise the factory path.
